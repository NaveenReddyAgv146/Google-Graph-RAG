## 1. Project Objective

Build an enterprise-grade Agentic GraphRAG solution that ingests internal business knowledge from PDFs, Google Slides, and GitHub repositories, builds a connected knowledge graph in Google Cloud Spanner Graph, and enables enterprise employees to discover relevant sales solutions through natural-language conversations.

The system provides grounded answers with supporting documents, code references, citations, and explicit relationships between assets.

## 3. Architecture & Monorepo Topology

Two independent ADK Python projects in one monorepo:

### A. Ingestion Copilot (`ingestion-copilot/`)
- **Role:** Asynchronous ambient worker handling batch ingestion, layout extraction, chunking, entity extraction, metadata generation, and graph commits.
- **Trigger Surface:** Cloud Storage / GitHub webhook notifications over authenticated Pub/Sub (`get_fast_api_app(trigger_sources=["pubsub"])`).
- **Human Review Gate:** Metadata review and approval through A2UI before committing to Spanner Graph.
- **Deployment Target:** Cloud Run in `asia-south1`.
- **Permissions:** Write access to Spanner Graph and GCS raw assets.

### B. Discovery Copilot (`discovery-copilot/`)
- **Role:** Interactive, multi-turn conversational Copilot featuring an ADK Planner Coordinator and specialist retrieval agents.
- **Workflow:** Query decomposition $\rightarrow$ RBAC pre-filtering $\rightarrow$ Hybrid Spanner GQL graph traversal + vector similarity $\rightarrow$ Deterministic MMR reranking $\rightarrow$ Evidence validation $\rightarrow$ Grounded synthesis with citations.
- **UI Surface:** A2UI declarative cards (lineage, citations, visual assets) and A2A protocol.
- **Deployment Target:** Google Agent Runtime in Gemini platform (`asia-south1`).
- **Permissions:** Read-only access to Spanner Graph snapshots and authorized assets.

### C. Shared Services (`common/`)
- **Unified Knowledge Plane:** Cloud Spanner Graph (`sales-discovery-trial` instance in `asia-south1`, `sales-knowledge-db`).
- **Object Storage & Backups:** Google Cloud Storage (`sales-discovery-mvp` in `asia-south1` / regional).
- **Shared Schemas & Utilities:** Graph ontology models, Vertex AI Embeddings client, Spanner connection pool, deterministic MMR reranker, and RBAC token validator.

## 4. Knowledge Graph Schema (Spanner Graph ISO GQL)

### Entities (Nodes):
1. `Document`: Internal business document (PDF / Slide deck / Repo)
2. `Chunk`: Segmented textual content with positional metadata
3. `Entity`: Discovered business entities, products, systems, people
4. `Repository`: GitHub repository metadata
5. `SourceFile`: Code source files within a repository
6. `Slide`: Presentation slide with presenter notes
7. `Technology`: Technologies, frameworks, libraries, cloud products
8. `BusinessSolution`: Documented customer solution, architecture, or project

### Relationships (Edges):
- `CONTAINS`: `(Document)-[:CONTAINS]->(Chunk)`, `(Repository)-[:CONTAINS]->(SourceFile)`
- `REFERENCES`: `(Chunk)-[:REFERENCES]->(Entity)`, `(Entity)-[:REFERENCES]->(Entity)`
- `MENTIONS`: `(Chunk)-[:MENTIONS]->(Technology)`
- `BELONGS_TO`: `(Slide)-[:BELONGS_TO]->(Document)`
- `SUPPORTS`: `(BusinessSolution)-[:SUPPORTS]->(Technology)`
- `DEFINES`: `(SourceFile)-[:DEFINES]->(Entity)`
- `CALLS`: `(SourceFile)-[:CALLS]->(SourceFile)`
- `IMPLEMENTS`: `(BusinessSolution)-[:IMPLEMENTS]->(Document)`

Every stored chunk and entity retains strict provenance: `file_path`, `page_number`, `slide_number`, `commit_sha`, `line_range`, and `gcs_uri`.

## 5. Retrieval & Reranking Architecture

1. **Query Planning:** Root coordinator breaks queries into entity targets and semantic themes.
2. **Permission Pre-filtering:** Enforce `DocumentAccess` checks against user principal groups before context injection.
3. **Graph Traversal:** 1-to-3 hop ISO GQL pattern matching for structural lineage.
4. **Vector Retrieval:** Spanner vector distance search (`COSINE_DISTANCE`) or Vertex Vector Search against chunk embeddings.
5. **Deterministic MMR Reranking:**
   $$\text{MMR} = \arg\max_{d_i \in R \setminus S} \left[ \lambda \cdot \text{Sim}_1(d_i, q) - (1 - \lambda) \max_{d_j \in S} \text{Sim}_2(d_i, d_j) \right]$$
6. **Evidence Verification:** Citation replacement callback guarantees inline Markdown references map to verifiable chunks.
7. **Lineage Presentation:** A2UI card generation displaying provenance path.

## 7. Security, RBAC & Governance

- Separate Service Accounts: `ingestion-copilot-sa` (Read/Write) and `discovery-copilot-sa` (Read-Only).
- Asset-Level RBAC: Documents and Chunks carry `rbac_groups`. Queries filter out unauthorized records before prompt assembly.
- Runner-wide Safety Plugins: LLM-as-judge guardrails preventing jailbreak or session-poisoning attacks.
- Secret Management: GitHub tokens and API keys sourced exclusively from GCP Secret Manager.

## 9. Evaluation Criteria & Thresholds

Scored using `agents-cli eval run`:
- `multi_turn_task_success` $\ge 0.85$
- `multi_turn_trajectory_quality` $\ge 0.80$
- `multi_turn_tool_use_quality` $\ge 0.85$
- `grounding` $\ge 0.90$
- `hallucination` $\le 0.05$
- `final_response_quality` $\ge 4.2 / 5.0$
- Unit tests (`pytest`) strictly validate deterministic functions (MMR calculation, GQL string builders, parsers).
